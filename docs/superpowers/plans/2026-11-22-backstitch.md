# Бэкстич — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Приложение само дорисовывает бэкстич (контраст и детали тоньше клетки), рисует его, даёт отмечать линию целиком и хранит в файле схемы v2.

**Architecture:** Чистый модуль `backstitch.js` (UMD) ищет стежки на мелкой сетке 4×4 на клетку и склеивает их в линии. `stitchfile.js` учится формату v2. `index.html` строит мелкую сетку, подбирает нитки, хранит `S.lines/S.lineDone`, рисует, считает прогресс и отмечает линии через существующий автомат жестов.

**Tech Stack:** ванильный JS, canvas 2D, `node --test`.

**Spec:** `openspec/changes/backstitch/specs/backstitch/spec.md`, `openspec/changes/backstitch/specs/chart-marking/spec.md`, `openspec/changes/backstitch/design.md`

## Global Constraints

- Без сборки и зависимостей; `backstitch.js` подключается `<script src="backstitch.js"></script>` рядом с `gestures.js`, в `ASSETS` `sw.js`; `VERSION = "stitchbook-v4"`.
- Узел `n = y*(w+1)+x`; стежок — пара соседних узлов (`|dx|≤1, |dy|≤1`, не равны); линия ≥ 2 стежков.
- Пороги `Tc = Td = {1:30, 2:22, 3:15}`, контраст при `dThr ≤ dSrc/2`; `K = 4`; детали — 2..8 точек-штрихов в клетке, шаблон ≥ 3 слотов из 4.
- Ползунок «Контуры»: `id="bs"`, `min=0 max=3 step=1 value=2`, подписи «нет / мало / средне / много».
- Нитки: повтор нитки схемы при `ΔE76 ≤ 10`, не больше 4 бэкстич-ниток (`bs:true, sym:"", count:0`).
- Формат: `v:2`, `lines:[{c, s:[n1,n2,…]}]`, `lineDone` RLE или `[]`; v1 → `lines:[]`, `lineDone:[]`; не больше 200 000 стежков.
- Попадание в линию: `≤ max(8, 0.3*S.view.s)` CSS px.
- Тесты: `node --test tests/*.test.js`.

## Review Focus

1. Схема без линий (ползунок «нет» или старая v1): прогресс, «↶», экспорт/импорт, список ниток работают как раньше; `lineDone` пустой не ломает RLE. Тест: Task 2 `v1 → пустые линии`, `v2 без линий`; Task 3 шаг браузерной проверки (f).
2. Отметка ряда крестиков, начатая на клетке, проходит через линию → линия не меняется. Task 3 проверка (c).
3. Выбрана нитка крестиков, касание по линии другой нитки → линия не переключается, а отмечаются крестики (если под точкой выбранная нитка). Task 3 проверка (d).
4. Большая схема (250 × ~360): построение не зависает дольше нескольких секунд. Task 3 проверка (g).
5. Линия на краю схемы (узлы `x = w` или `y = h`) рисуется и отмечается. Task 1 тест `контраст у края`.

### Task 1: Поиск бэкстича `backstitch.js`

**Files:**
- Create: `backstitch.js`
- Test: `tests/backstitch.test.js`

**Interfaces:**
- Produces: `Backstitch.find({w, h, k = 4, sub, grid, palette, level, pickThread, T}) → [{c, segs: [[n1,n2], …]}]`
  - `sub: Float32Array` длины `(k*w)*(k*h)*3`, Lab по строкам мелкой сетки;
  - `grid: Int32Array(w*h)`; `palette: [{lab:[L,a,b]}]`;
  - `level: 0..3`; `pickThread(lab:number[3], kind:"contrast"|"detail") → number`;
  - `T` (необязательно) — переопределение порогов `{tc:{1,2,3}, td:{1,2,3}}`;
  - в каждом стежке `n1 < n2`; линии отсортированы не требуется.

Алгоритм — `design.md`, «Модуль backstitch.js», шаги 1–3 (средние Lab двух рядов у границы; фон `Lbg` по блоку 3×3 клеток — можно префиксными суммами; шаблоны со слотами и порядком ничьих `\`, `/`, верх, низ, лево, право; union-find по общим узлам внутри нитки; при совпадении стежка у контраста и детали — контраст).

- [ ] **Step 1: Write the failing tests** — хелпер `img(w, h, fn)` строит `sub` (k=4), где `fn(sx, sy) → L` (a=b=0); `pick = lab => lab[0] < 50 ? 1 : 0` (нитка 0 — светлая, 1 — тёмная) если не сказано иное.
  - `контраст на резкой границе при одинаковой нитке`: w=6,h=4; L=70 при `sx<12`, иначе L=40; grid весь 0; palette `[{lab:[55,0,0]}]`; level 2 → одна линия, 4 вертикальных стежка с x=3 (`n1 = y*7+3`, `n2 = (y+1)*7+3`).
  - `нет линии при контрастных нитках`: та же картинка, grid 0 слева (x<3), 1 справа, palette `[{lab:[70,0,0]},{lab:[40,0,0]}]` → `[]`.
  - `нет линии на плавном градиенте`: L = 40 + sx (w=10 → перепад между соседними клетками 4) → `[]`.
  - `тонкая диагональ — диагональные стежки`: w=h=6, L=80, кроме `sx===sy` → L=20; grid 0, palette `[{lab:[80,0,0]}]`; → одна линия, все стежки вида `[y*7+y, (y+1)*7+y+1]`, не меньше 4.
  - `галочка — две диагонали с общим узлом`: w=6,h=4, L=85, тёмные точки на `sx∈[4..7], sy = sx` (клетка (1,1), диагональ `\`) и `sx∈[8..11], sy = 15−sx` (клетка (2,1), диагональ `/`) — V с вершиной в узле x=2,y=2; → одна линия из 2 стежков, общий узел `2*7+2`.
  - `тонкая горизонталь посреди клеток`: L=80, тёмная строка `sy===5` (внутри клетки y=1, строка 1 → «верх» клетки y=1) → горизонтальные стежки на y=1.
  - `однотонная картинка — пусто`, `level 0 — пусто` (на картинке из первого теста).
  - `level 3 не меньше level 1`: на картинке «диагональ + граница» число стежков при level 3 ≥ при level 1.
  - `одиночный стежок выбрасывается`: тёмный штрих длиной в одну клетку → `[]`.
  - `разные нитки — разные линии`: `pickThread` возвращает 2 для `sx<12`-стороны детали и 3 для другой… проще: две диагонали, разнесённые на 2 клетки, `pick` по L (L=20 → 1, L=30 → 2) → две линии с разными `c`.
  - `контраст у края`: граница по `y` между клетками рядов 2 и 3 на w=4,h=5 → горизонтальные стежки с узлами `x = 0..4` включительно (крайний стежок до узла `x = w`).
